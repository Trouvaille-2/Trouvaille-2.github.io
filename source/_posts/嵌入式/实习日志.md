### crc校验

串口通信在物理线路上传输时，会有噪声干扰、波特率偏差、线路接触不良等问题，导致某些字节在传输中变错。比如 下位机 回你 0x066B，线路一抖变成 0x066F，上位机根本不知道。

CRC（循环冗余校验）解决这个问题，思路很简单，像行李标签：

发送方：对帧内容算出一个 16 位的"指纹"（CRC 值），贴在帧末尾一起发出去
接收方：收到后对帧内容重新算一遍指纹，跟收到的指纹对比
一样 → 数据没问题，放心用
不一样 → 数据在传输中坏了，丢弃这帧
Modbus RTU 协议强制要求每帧都带 CRC16

Modbus代码示例，包括crc校验，读数据请求帧，读数据返回帧

```python
"""
modbus_frame.py — Modbus RTU 帧构建与解析（链路①第2步）

本模块只负责"打包/拆包"，不负责收发。
收发（串口）在后面的步骤再做。

帧格式速查（RTU 模式）:
  读请求: [从机地址1B][功能码1B][起始寄存器2B][数量2B][CRC16 2B]
  读响应: [从机地址1B][功能码1B][字节数1B][数据N×2B][CRC16 2B]
"""


def crc16_modbus(data: bytes) -> int:
    """计算 Modbus CRC16 校验值

    规则: 初始值 0xFFFF, 多项式 0xA001, 逐字节异或后按位右移
    """
    crc = 0xFFFF
    for byte in data:
        crc ^= byte
        for _ in range(8):
            if crc & 0x0001:
                crc = (crc >> 1) ^ 0xA001
            else:
                crc >>= 1
    return crc


def build_read_frame(slave: int, start_reg: int, count: int) -> bytes:
    """组装"读保持寄存器"请求帧（功能码 0x03）

    参数:
        slave:     从机地址（EPC100 用 1）
        start_reg: 起始寄存器号（如 37 = 设定值）
        count:     要读几个寄存器（连续读）
    返回:
        完整的 8 字节请求帧
    """
    # 1. 从机地址 + 功能码
    body = bytes([slave, 0x03])

    # 2. 起始寄存器号 → 2 字节大端（高字节在前，Modbus 规定）
    body += start_reg.to_bytes(2, "big")

    # 3. 数量 → 2 字节大端
    body += count.to_bytes(2, "big")

    # 4. CRC 对前面所有字节计算，2 字节小端附加（低字节在前）
    crc = crc16_modbus(body)
    return body + crc.to_bytes(2, "little")


def parse_read_response(resp: bytes, count: int) -> list:
    """解析"读保持寄存器"响应帧，返回寄存器值列表

    参数:
        resp:  下位机回的一整帧字节
        count: 我们请求读了几个寄存器（用于校验）
    返回:
        [reg值1, reg值2, ...]（每值 0~65535）
    """
    # 1. 长度校验：3固定头 + 数据 + 2CRC
    expect_len = 3 + count * 2 + 2
    if len(resp) != expect_len:
        raise ValueError(f"响应长度不对: 期望{expect_len}字节, 实际{len(resp)}字节")

    # 2. 功能码校验（下位机回什么功能码，我们就要什么）
    if resp[1] != 0x03:
        raise ValueError(f"功能码异常: 0x{resp[1]:02X}")

    # 3. 字节数字段校验（第3字节应等于 数量×2）
    if resp[2] != count * 2:
        raise ValueError(f"字节数与请求不符: {resp[2]} != {count * 2}")

    # 4. CRC 校验（收到帧的后2字节 vs 对前段重算）
    recv_crc = int.from_bytes(resp[-2:], "little")
    calc_crc = crc16_modbus(resp[:-2])
    if recv_crc != calc_crc:
        raise ValueError(f"CRC校验失败: 收到{recv_crc:04X}, 计算{calc_crc:04X}")

    # 5. 逐个提取寄存器值（每值 2 字节大端）
    values = []
    for i in range(count):
        seg = resp[3 + i * 2 : 3 + i * 2 + 2]
        values.append(int.from_bytes(seg, "big"))
    return values


if __name__ == "__main__":
    # ========== 自测 1：用 Modbus 官方标准向量验证 CRC ==========
    frame = build_read_frame(1, 0, 10)
    print("读请求帧:", frame.hex())
    assert frame.hex() == "01030000000ac5cd", "CRC 或字节序有误！"
    print("标准向量验证通过 [OK]")

    # ========== 自测 2：响应解析 ==========
    # 模拟下位机回：地址1, 功能码3, 4字节, 数据 0x066B=1643, 0x066F=1647
    resp = bytes([0x01, 0x03, 0x04, 0x06, 0x6B, 0x06, 0x6F])
    resp += crc16_modbus(resp).to_bytes(2, "little")   # 补上正确 CRC
    values = parse_read_response(resp, 2)
    print("解析出的寄存器值:", values)
    assert values == [1643, 1647], "解析结果不对！"
    print("响应解析验证通过 [OK]")


```

3.读取数据

```python

"""
modbus_client.py — 上位机业务层雏形：读写 EPC100 寄存器（链路①第4步）

到这里，链路①就通了：
    上位机逻辑(本文件) -> 请求帧 -> 模拟下位机 -> 响应帧 -> 上位机解析

寄存器约定（和真实项目一致）：
    读 reg37 = 设定值 SETPOINT
    读 reg44 = 反馈值 FEEDBACK
    写 reg35 = 内环 P 增益（x100 存储，写 800 表示 8.00）

以后接真实硬件时，本文件只有一处要换：
    sim_slave.handle_request(req)  ->  串口发请求、收响应
所以这个文件刻意把"业务逻辑"（read_reg/write_reg）和
"收发方式"（handle_request）分开，换硬件不动业务。
"""

from modbus_frame import (
    build_read_frame, build_write_frame,
    parse_read_response, parse_write_response,
)
import sim_slave


def read_reg(reg: int) -> int:
    """读单个寄存器：拼请求 -> 交给下位机 -> 解析响应 -> 返回值

    读 1 个寄存器返回的列表只有一个元素，[0] 把它取出来。
    """
    req = build_read_frame(1, reg, 1)
    resp = sim_slave.handle_request(req)
    return parse_read_response(resp, 1)[0]


def write_reg(reg: int, value: int) -> int:
    """写单个寄存器，三步曲：写 -> 校验回显 -> 回读验证

    工业惯例：光"写出去"不算数，必须确认下位机真的收下了：
    1. 写：发 0x06 请求
    2. 校验回显：下位机回的原样帧必须和我们发的一致
    3. 回读验证：再读一遍该寄存器，值必须变成新值
    """
    # 1. 写
    req = build_write_frame(1, reg, value)
    resp = sim_slave.handle_request(req)
    resp_reg, resp_val = parse_write_response(resp)

    # 2. 校验回显
    if resp_reg != reg or resp_val != value:
        raise ValueError(f"写入回显不符: 期望reg{reg}={value}, 收到reg{resp_reg}={resp_val}")

    # 3. 回读验证
    back = read_reg(reg)
    if back != value:
        raise ValueError(f"回读验证失败: 期望{value}, 读到{back}")
    return back


if __name__ == "__main__":
    # ========== 链路①演示：读 -> 写 -> 读 ==========

    # 1. 读设定值、反馈值
    setpoint = read_reg(37)
    feedback = read_reg(44)
    print(f"设定值={setpoint}, 反馈值={feedback}")

    # 2. 写 reg35（内环P）: 从 5.00 改成 8.00
    print("写 reg35: 500 -> 800 ...")
    verify = write_reg(35, 800)
    print(f"写入成功, 回读={verify}")

    # 3. 再读一遍，确认模拟下位机的寄存器表真的变了
    setpoint = read_reg(37)
    p = read_reg(35)
    print(f"再读: 设定值={setpoint}, 内环P={p}")
    print("链路①打通 [OK]")


```

crc校验算法的代码：
>1 初始化一个16位的寄存器地址 用作初始值
2 遍历数据字节，从最高位到最低位， 
3 将数据字节与寄存器异或
4 对寄存器进行8次迭代，每一次迭代将寄存器右移一位
5 如果最低位位1，将寄存器与生成多项式0x8005异或，否则只进行右移操作
6 重复上述步骤直到遍历完所有的字节
7 最终寄存器的值就是crc16校验码
8 crc计算之后高低位进行互换

```c
uint16_t modbus_crc16(const uint8_t *data, size_t length)
{
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < length; i++)
    {
        crc ^= data[i];
        for (int j = 0; j < 8; j++)
        {
            if (crc & 0x0001)
            {
                crc >>= 1;
                crc ^= 0xA001;
            }
            else
            {
                crc >>= 1;
            }
        }
    }
    return crc;
}
```
